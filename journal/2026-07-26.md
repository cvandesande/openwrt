### 2026-07-26, fourteenth session — 1G PHY driver found missing

Investigation only; the flash followed in the fifteenth session.

**The three 1G ports are MaxLinear GPY115C PHYs running on the Generic
driver.** Live `phy_id` `0x67c9df10` = `PHY_ID_GPY115C` (`mxl-gpy.c:23`), all
on one MDIO bus `mdio@fd000` at addresses 0/1/2. `CONFIG_MAXLINEAR_GPHY` is
`is not set` in `target/linux/generic` and was never overridden. Mono's own
Armbian support (armbian/build#9640, same author as our DTS) sets it.

Consequence: `genphy_read_status()` leaves `->link` at the latch-low BMSR
value, which in polling mode is deliberate — the latch exists so momentary
drops are caught. With no PHY `interrupts` property (absent in the vendor DTS
too, and `mxl-gpy` sets `PHY_F_NO_IRQ` regardless) phylib polls at 1 Hz, so any
brief loss of sync becomes a **full one-second link-down** with the bridge
dropping the port. `mxl-gpy`'s `gpy_read_status()` overrides `->link` from
`PHY_MIISTAT`, a live non-latching register, so recovered glitches cause no
outage. Measured on `eth1`: 142 events in 5.6 days, ~130 at 1.03–1.05s and the
rest exact multiples; the far-end mt7530 logged none in over five days; MAC
counters clean across 77.7M frames.

Fix is `CONFIG_PACKAGE_kmod-phy-maxlinear=y` in the seed — *not*
`CONFIG_MAXLINEAR_GPHY=y`, which silently ships nothing (see the kmod gotcha
below). Load ordering is safe:
`sdk_dpaa` connects the PHY from `dpa_start()` (ndo_open, at ifup), so the
`AutoLoad,18` pass registers the driver before netifd brings interfaces up.
Commits (pushed; both tips verified against origin 2026-07-26): `mono-ask`
`5db4b7b6d3` + `66c8466c30`, `mono-ask-25.12` `6ef7c478a8` + `6c21493790`. Image
verified by manifest, both `.ko`s, `/etc/modules.d/18-phy-maxlinear`, fwtool +
gzip — then flashed; outcome in the fifteenth-session digest.

**eth2 transmit timeouts — explained, no action.** Nine `NETDEV WATCHDOG`
events, one cluster, never repeated. Cause is 802.3x PAUSE from the peer:
287,414 pause frames on `eth2` versus 28 on `eth1`. The peer is a Realtek
RTL8156B (`r8152`) in a Dell monitor dock, **KVM-shared between two machines** —
every KVM switch detaches the NIC from one host's USB bus while the copper link
stays up, so the FIFO fills and it pauses the router. Structural, not a fault;
a brief stall is acceptable.
