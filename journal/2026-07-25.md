### 2026-07-25, thirteenth session — r8 folded into patch 012, built, installed

r8 shipped to both branches and installed on the router, but **never loaded**
(see open item 2). Durable method and traps:

- **Regenerate patches from the pristine tarball, do not hand-edit.** Extract
  `dl/selinux-policy-2.8.4.tar.zst` → apply 010+011 for a base → apply 012 and
  overwrite the changed files → `diff -Naur base new`. A normalized diff of old
  vs new patch then shows only the intended delta plus recomputed hunk counts.
  Strip `patch`'s `.orig` backups from both trees first or they leak in as
  spurious hunks.
- **`patch --dry-run` on a SERIES is meaningless.** Dry-run does not modify the
  tree, so each patch is tested against an unmodified base; it reported 011 as
  failing when it applies fine. Only real sequential application tells you
  anything.
- **The leading dot is load-bearing** in CIL: `.runtmp.` is the absolute
  generic `/tmp/run`; bare `runtmp.` inside the mwan3 block resolves to
  `.mwan3.runtmp`. r8 uses both deliberately — they are NOT redundant.
- **No `setools` (`sesearch`/`seinfo`) on the build host**, so allow rules
  cannot be read out of a compiled policy. `secilc` resolves macro calls at
  compile time, so a bad macro fails the build rather than silently no-op'ing —
  which is the indirect evidence you are left with.
- **`/etc/selinux/config.apk-new` is left behind by apk and says
  `SELINUX=permissive`** (the package default) while the live config stays
  enforcing. Harmless, but never let anything `mv` it into place — that is the
  same mechanism behind "first boot after a flash runs permissive".
